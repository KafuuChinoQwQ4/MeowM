# 本地优先个人收支管理

安卓优先、离线可用的个人账本。Rust 工作区承载领域模型、账务用例、导入解析、通知解析和备份逻辑；Tauri + React + TypeScript 提供界面，Android 使用 Tauri WebView 壳。

## 目录约定

每个目录的 `tree` 只描述该目录的直接文件。新增或删除文件时，先更新 `scripts/tree_descriptions.json`，再运行 `python3 scripts/update_tree.py`；用 `python3 scripts/update_tree.py --check` 检查索引。生成目录 `gen`、构建产物及已退役界面目录不生成索引，避免将 `tree` 当成 Android 资源编译。

账本核心、每日收支、平台管理、交易编辑/撤销、账单导入待确认、报表与预算流程已接通 SQLite。Android 通知采集、周期账单及搜索分类规则已接通 React 界面，备份模块尚未接入界面。

## 收支与可选参考余额

新平台默认不记录初始金额，日末余额显示“尚未设置”，收入、支出和净额仍按已确认流水统计。设置参考余额时，金额代表所选本地日期的日末余额。例如 4 号日末为 100 元，5 号净收入 20 元，则 5 号日末为 120 元；若 4 号净收入 15 元，则 3 号日末为 85 元。

每个平台独立保存一个参考金额和时间，再次设置会替换参考点；清除参考不会删除流水。参考金额本身不产生流水，查询根据最新的已确认流水推算。余额支持零和负数，金额使用整数分计算。数据库自动升级到版本 8，保留旧账户金额、时间和流水，不会自动清理旧账本。

## 运行界面

```bash
cd apps/tauri-ui
npm ci
npm run tauri -- dev
```

桌面需要 Tauri 的系统构建依赖。数据库位于 Tauri 应用数据目录下的 `ledger.sqlite3`，Android 使用应用私有存储。首次启动创建微信、支付宝、现金三个无参考余额的平台。「新建平台」可添加其他平台，顶部选择平台和日期，「记一笔」保存所选日期的收支（本地中午），「设置参考余额」保存所选日期的日末参考金额。当前手动录入使用人民币。

## Android 打包

需要 JDK 17、Android SDK 35 和 36（Tauri Android 库需要 36）、NDK（已验证 26.1.10909125）和 Rust Android target。Gradle 由 Android 工程的 wrapper 提供。

```bash
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_NDK_ROOT="$ANDROID_HOME/ndk/26.1.10909125"
export JAVA_HOME=/path/to/jdk17
export PATH="$JAVA_HOME/bin:$PATH"
rustup target add aarch64-linux-android x86_64-linux-android
bash scripts/build_android.sh arm64-v8a
# 模拟器
bash scripts/build_android.sh x86_64
```

调试 APK 位于 `apps/tauri-ui/src-tauri/gen/android/app/build/outputs/apk/` 下的架构目录，安装时指定对应设备与实际文件路径：

```bash
adb -s DEVICE_SERIAL install -r /path/to/app-debug.apk
adb -s DEVICE_SERIAL shell am start -n com.example.localledger/.MainActivity
```

应用 ID 沿用 `com.example.localledger`。覆盖安装保留数据，旧账本清理需单独执行且只针对指定设备；启动逻辑不删除数据。

## 平台管理

左下角打开导航，进入「平台管理」可新建平台、重命名、修改分类及切换到账本。支持支付钱包、银行账户、证券账户、虚拟币交易所、现金、其他六类；列表支持分类筛选和分页。分类存入 SQLite 的 `platform_metadata` 表，重命名保留原账户 ID 和全部流水。旧微信/支付宝默认为支付钱包，现金默认为现金，其他旧平台默认为其他。当前仍按人民币记账，分类不包含多币种换算、持仓或行情同步。

## 报表与预算

导航中的「报表总览」提供本月或自定义日期范围的收支、月度趋势、分类占比、分页商户排行和期末平台余额。支持平台、分类和商户筛选；仅统计已确认交易，退款抵减支出，未单独分类的退款沿用原消费分类，转账不计收支但影响余额。日期按设备本地时区换算为 UTC 半开区间，结束日期当天不计入。

「预算管理」支持自然月或自定义周期，按全部或指定平台、分类新增和编辑额度。进度按预算完整周期计算，停用后仍保留预算及历史进度，可编辑重新启用。同一周期和范围只能有一份预算；新目标不能选择已停用分类。80% 提示接近额度，达到额度和超支分别提示。当前提醒显示在报表页面，不写入交易，也不发送系统通知。

预算金额和报表总额由 Rust 使用整数分计算，IPC 金额及预算百分比使用字符串，图表仅转换显示比例。固定 UTC+8 和纽约 DST 月份边界、退款撤销、重启持久化及超支边界均有真实 SQLite 测试；浏览器交互测试仍模拟 IPC，Android 实机验收尚未进行。

## Android 通知采集

导航进入「通知采集」，阅读用途说明并勾选同意，再分别启用微信、支付宝来源。可选择默认人民币平台，也可在收件箱中手动补全平台。通过「打开系统通知访问设置」授予本应用通知访问权限；页面分别显示系统授权和服务连接状态，返回页面或点击刷新可更新状态。

通知只生成待确认记录，不自动入账。缺少商户、金额或关联信息时需要补全；转账须选择转出、转入平台，退款须关联原消费。收件箱支持刷新、修改、确认和忽略。关闭来源后停止处理新事件，保留已有候选；撤销系统权限会停止监听。系统隐藏内容、后台限制及通知格式变化都可能造成漏采，可使用账单导入补齐。

Android 仅将受支持包名、标题、正文、通知 key 和发布时间在内存中传入 Rust。数据库保存标准化交易、来源摘要及结果码，不保存原始正文或 key；通知监听与 WebView 使用同一私有数据库。收据与 Pending 在同一事务写入，服务重连会重放当前活动通知，重复回调和服务重建均复用原候选。

第四阶段的构建和验收记录见 [通知采集验收](docs/stage4-notification-validation.md)。模拟事件验证不能代替真实微信、支付宝支付或不同厂商后台策略的实测。

## 周期账单

导航进入「周期账单」，按人民币平台添加收入或支出计划，可设置金额、分类、商户、备注、每周/每月/每年周期、1 至 120 的重复间隔、首次到期日及可选结束日期（含当天）。短月会落到月末，后续月份仍按原始日期计算；例如 1 月 31 日 → 2 月 28 日 → 3 月 31 日，闰日年账单同样保留原锚点。

支持编辑未来账单、暂停、恢复、跳过下一次和查看最近 200 个实例。暂停保留游标，恢复会补生成暂停期间到期的候选；跳过会留下持久收据，不产生交易。改变周期或下一次到期日后重新起算，新日期须晚于已生成或跳过的实例。改金额、平台、分类等不会改写已有候选。

应用启动、返回前台、前台每分钟及手动刷新时按设备本地日期检查到期，单次最多处理 200 个实例；积压更多时可点击继续生成。到期记录携带周期来源进入待确认，确认后才计入余额、报表和预算。首页列出未来 7 天内的下一次到期及逾期待确认账单，已生成项可进入按「周期账单」来源筛选的收件箱；未到期项会在到期后生成。实例状态与候选的确认、忽略或恢复状态同步。

当前提醒显示在应用内，应用关闭时不调度系统后台闹钟或系统通知。验证记录见 [周期账单验收](docs/stage5-recurring-validation.md)。

## 搜索与分类规则

导航进入「搜索与分类」可跨日期搜索全部流水，组合关键词、商户、状态、来源、平台、分类、日期和人民币金额范围；日期上限不含当天。结果按时间倒序、同一时刻按 ID 稳定排序，支持分页、详情跳转、清除筛选和导出当前筛选结果为 UTF-8 CSV；Android 会打开系统“另存为”选择器，桌面通过浏览器下载。搜索关键词也匹配已保存的来源外部交易号；来源摘要只有不可逆哈希，不能反查原文。

「分类规则」中可创建、停用分类，维护商户别名，按优先级编辑商户/备注包含规则。创建或编辑前须预览总命中和受影响的未手工分类待确认候选，再确认保存。商户原文始终保留显示，规范化值和别名仅用于匹配。建议在收件箱查看，点击「采用建议」后才写入候选；已手工分类或已确认交易不会被规则批量覆盖。分类和别名存于本地 SQLite，数据库迁移 8 保留旧交易和旧规则。

本阶段验收见 [搜索与分类验收](docs/stage6-search-validation.md)。
