# OKX 行情与加密资产流程

以用户在本次请求中给出的四项流程为实施范围，沿用 Rust 本机直连和系统凭据存储。

- 行情：无需凭据读取 SPOT tickers、当前及历史 K 线，持久化自选，提供周期选择、手动刷新和加载更早数据。
- 资产：区分交易账户与资金账户；数量、可用、冻结和权益保持十进制字符串。USD 估值使用 OKX asset-valuation，注明可能包含赚币账户；不把合约名义价值加入净资产。
- 流水：读取 7 天/3 个月账单、3 个月现货成交、充值和提现，按用户 UID、来源和平台 ID 去重。账单两种时间窗口共用来源 ID。成交保留买入/卖出两条资产腿及独立费用，实际报价资产使用 tradeQuoteCcy（兼容统一 USD/USDC 订单簿）；账单为核对记录，充值提现保留平台状态。确认与忽略仅写入独立加密资产记录，未完成或失败的充提不能确认。
- 合约：单独展示 SWAP/FUTURES 当前及 3 个月历史持仓，区分未实现盈亏、已实现净盈亏、手续费和资金费；不对不同结算币种求和，不再次从 realizedPnl 扣费用。
- 持久化：SQLite schema 15 添加自选和加密记录，随加密备份恢复和全量清理；不扩充法币 CurrencyCode 或影响现有收支。
- 错误：异步 Rust 请求不持账本锁，提交前再次检查锁状态与会话代次，凭据切换、锁定、清空及恢复使旧任务失效，分页绑定原账户 UID；有限响应大小、超时、参数校验和安全错误类别。分页显式展示剩余页，部分失败不伪装成功。
- 验收：精确转换、去重与状态转换、备份/清理、协议签名和公共无鉴权请求、移动端四流程及现有连接回归。没有真实凭据时明确区分协议测试与私人账户联调。

依据：[OKX API v5 官方文档](https://www.okx.com/docs-v5/en/)。
