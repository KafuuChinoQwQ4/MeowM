# OKX 公开数据、私有账单与交易设计

## 目标

用户打开 OKX 后，无需填写 API 凭据即可查看公开现货行情。需要账户数据时，用户自行创建并填写只读 API Key；需要下单时，再单独填写模拟盘或实盘交易 Key。应用支持用户主动提交的现货、永续合约和交割合约订单，并保留每笔请求的明确环境标识和确认步骤。

## 现状

现有 Rust/React/Tauri 流程包括无鉴权现货行情、账户资产与估值、账单/成交/充值/提现读取、独立加密流水核对及 SWAP/FUTURES 持仓读取。OKX 工作区入口目前被凭据配置状态挡住，交易客户端只支持 GET，现有凭据存储为单个 OKX 密钥组。当前协议没有下单、挂单查询或撤单能力，也没有写入法币流水的加密资产流程。

## 方案

### 凭据与环境

- 公共行情在未配置凭据时可访问。
- 现有 OKX 凭据组继续用于只读账户与历史数据。
- 新增独立的模拟盘与实盘交易凭据组，分别保存 API Key、Secret Key 和 Passphrase。每组由用户在 OKX 创建并输入，使用本机系统安全凭据存储；界面不回显。
- 设置说明要求交易 Key 开启 Read 与 Trade，不开启 Withdraw，并建议在 OKX 为 Key 配置 IP 白名单。应用不会创建或修改 OKX 权限。
- 默认选择模拟盘。切换到实盘必须由用户显式选择；提交订单前的预览和第二次确认均清楚展示当前环境。
- OKX Demo 请求添加 `x-simulated-trading: 1`；实盘请求不带该标头。

### 交易范围

- 交易品种仅支持 `SPOT`、`SWAP` 和 `FUTURES`；不支持杠杆现货、期权、事件合约、借币、划转、充值或提现。
- 支持市价和限价订单。现货市价单按 `tgtCcy` 指定收到的币种：买入输入基础币数量、卖出输入报价币数量，并设置 0–5% 的滑点容差（默认 1%，精确到百分比小数点后两位）；确认页同时显示行情价格及估算另一侧金额。现货限价单使用基础币数量和限价。界面明确标注每种订单的数量单位。
- 永续/交割合约订单以张数输入。调用公开合约信息读取交易状态、价格步长、数量步长、最小数量和合约面值；仅允许 `live` 状态及符合规格的请求。处于 `post_only`、`suspend`、`preopen` 等状态的品种暂不开放下单。
- 合约界面支持开多、开空、平多、平空。读取账户当前 `posMode`，按 net 或 long/short 模式构造请求；net 模式平仓发送 `reduceOnly=true`，long/short 模式必须指定 `posSide`。由用户选择该订单的 cross/isolated `tdMode`。平仓数量校验当前对应仓位及已挂平仓量，最终仍以 OKX 对竞态和可平数量的校验为准。显示合约面值、结算币、当前杠杆信息（可读取时）和保证金模式。
- 不调用设置杠杆、设置持仓模式、切换账户模式或任何资金转移接口。应用源码只允许固定的下单、订单查询与撤单端点。
- 每个下单请求先进入订单预览，显示品种、方向/开平、订单类型、价格/数量/币种、保证金模式、环境及估算名义价值；用户再次确认后才发送。订单确认可取消。
- 提供当前挂单、近 7 天订单历史和单笔详情。撤单须选择具体订单并再次确认；成交状态以 OKX 查询结果为准。
- 订单 ID 由客户端生成并随请求使用。提交超时或连接中断时，界面展示“结果未确认”和该 ID，先按该 ID 查询订单状态；不自动重发下单 POST。

### 组件与数据边界

- `connectors::credential_store` 管理现有只读凭据和新增的模拟/实盘凭据组。
- `connectors::markets::okx` 保留公开行情和 GET 签名，增加带 JSON body 的私有 POST 签名、Demo 标头、产品/账户读取和固定下单端点。
- `crypto::commands` 公开类型化的读取、提交和撤单命令。IPC 不接受 URL、HTTP 方法或可变端点；服务端再次校验订单规格。网络请求在阻塞任务中运行，不持账本锁。
- `features/markets/okx` 增加交易页和订单确认视图；连接设置分别呈现只读、模拟交易和实盘交易凭据状态。无凭据时行情仍可使用，私有和交易操作显示配置入口。
- 订单请求/响应和订单状态留在 OKX 账户及界面状态，不写入法币交易、分录、预算、报表或加密流水表。

## 错误与安全行为

- 对 GET 和 POST 的签名串按 OKX 要求精确包含时间戳、方法、完整路径/查询串和原始请求体；API 密钥不进入 URL、日志或错误文案。
- 数据读取错误允许用户重试；下单 POST 不自动重试。收到成功响应只表示 OKX 接受请求，不当作已成交；逐笔状态以订单查询为准。
- `clOrdId` 用于重查网络结果不明的请求。服务端不从前端接收任意路径，也不会提供撤单以外的任何写端点。
- 账户配置、合约规格或持仓读取失败时禁用相应订单操作并显示可重试错误；不使用旧规格或 JS 浮点数放宽校验。
- 实盘切换显著标记在交易页、订单预览、二次确认和结果区域。

## 验收

1. 无凭据时 OKX 页面可以加载行情；私有页显示设置入口；只读、模拟盘和实盘凭据可分别保存、替换、删除并通过系统安全凭据存储调用。
2. 本地协议测试验证公共请求不带凭据，Demo 标头和 GET/POST 签名匹配发送内容；订单参数、金额步长、最小量、合约模式和订单状态解析均有精确测试。
3. Rust 本地 HTTP 测试证明 UI 预览不会发下单请求，只有二次确认才发固定的订单端点；超时不触发自动重发；撤单只针对明确选中的订单。
4. 浏览器测试覆盖无密钥行情、私有凭据引导、默认模拟模式、实盘显式切换、现货市价/限价预览、永续/交割开平仓预览、确认发送、挂单刷新、撤单确认及小屏布局。
5. 验证 Rust workspace 测试、前端构建和相关浏览器测试、格式、生成目录索引。真实实盘和模拟账户请求仅在用户本机填入凭据后可验证；本次自动测试不提交真实订单。
