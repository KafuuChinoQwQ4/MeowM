# 本机支付与市场 API 只读接入

日期：2026-10-31

状态：用户已批准设计，规格待评审

## 目标

为 MeowM 增加由本机用户配置、直接连接平台的只读 API 集成。支付 API 用于读取商户账单；交易所 API 用于读取账户余额；同花顺 iFinD 用于读取行情。增加独立的「交易所」导航页，为后续其他交易所留出扩展位置。

MeowM 目前是 Tauri、React、Rust 和本机 SQLite 组成的 Android 优先个人账本。外部请求继续由 Rust 发出并通过 Tauri IPC 暴露必要结果。应用不增加服务端，不把平台 API 代理给其他用户或网络客户端。

## 范围

首期支持以下连接测试和只读查询：

| 平台 | 接入身份 | 首期调用 | 返回给界面的信息 |
| --- | --- | --- | --- |
| 微信支付 | 商户号及商户 API V3 证书材料 | 申请指定日期的交易账单，下载账单并校验平台返回的摘要 | 账单日期、校验状态及安全的概览结果 |
| 支付宝 | 商户应用及签名密钥材料 | 查询指定日期的商户账单下载地址并读取账单 | 账单日期、读取状态及安全的概览结果 |
| 币安 Spot | API Key 与 Secret，配置为只读 | 查询现货账户信息 | 非零币种及可用余额摘要 |
| 欧易 | API Key、Secret 与 Passphrase，配置为只读 | 查询账户余额 | 币种及可用余额摘要 |
| 同花顺 iFinD | iFinD HTTP API refresh token | 换取短期 access token，并查询默认测试标的 `000001.SZ` 的最新行情 | 标的代码、行情时间与报价字段 |

微信和支付宝连接针对商户自己的账单，不用于读取个人钱包账单。个人账单继续使用现有文件导入和 Android 通知采集。微信账单 API 有日期范围和生成时限，下载链接短时有效，账单文件须按接口响应校验摘要；UI 允许用户选择账单日期，Rust 服务在一次请求流程中完成申请、下载和校验。[微信支付开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071218)

币安、欧易的 API Key 只需要只读权限；本期不接受交易、提现或转账权限。iFinD 以行情数据服务接入，不展示为证券交易账户；HTTP API 使用长期 refresh token 换取短期 access token，再调用行情端点。[币安 Spot API 权限](https://developers.binance.com/en/docs/products/spot/rest-api) [欧易 API 权限](https://app.okx.com/docs-v5/en/) [iFinD HTTP API 认证与行情示例](https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/example.html)

本期不自动写入账本或待确认列表，不实现自动定时同步、历史交易导入、持仓盈亏计算、行情图表、买卖下单、退款、收款、转账和提现。后续功能复用本期连接与凭据层逐项增加。

## 界面

- 在现有主导航增加「交易所」视图，内部 route 使用 `markets`，避免与已存在的 `exchange`（「法币汇率」）冲突。
- 「交易所」页包含币安、欧易、同花顺 iFinD 三张连接卡片；支持配置凭据、测试连接和断开。额外交易所只显示「后续接入」占位，不伪装成已连接。
- 微信支付、支付宝 API 配置放在「设置 → 平台与采集」下的 API 连接区，不增加主导航入口。
- 已保存凭据只显示掩码和是否已配置。测试结果显示成功、凭据错误、权限不足、账单不可用、网络超时、限流或平台错误等可操作状态；不向 UI 返回密钥、签名、完整下载 URL 或原始响应正文。
- 支付账单测试需要用户指定平台允许查询的历史日期。成功后只显示安全摘要，不自动入账。

## 架构与数据流

1. React 页面通过类型化 API 封装调用 Tauri 命令；HTTP、请求签名、响应校验及 provider 错误映射全部在 Rust 完成。
2. `connectors` 模块提供支付平台和市场数据 provider 的公共连接状态与连接测试接口。每个平台独立实现参数校验、认证签名、超时、状态码映射和响应解析。网络请求不持有账本互斥锁。
3. 凭据经 IPC 一次性传入 Rust，写入 Android Keystore 加密支持的系统凭据存储或桌面系统凭据存储。读取时用 `Zeroizing` 限制密钥在内存中的生命周期。没有安全凭据后端的平台不得回退为明文文件或 SQLite 存储。
4. 数据库备份、导出、日志和 UI DTO 不含任何平台凭据。应用重装或系统凭据清除后，连接状态显示为需重新配置；备份恢复不恢复平台 API 密钥。
5. 连接测试只返回必要摘要和脱敏状态。临时账单 URL、签名串、完整商户响应和 access token 不持久化；iFinD access token 按其有效期缓存于进程内，refresh token 留在系统安全凭据存储。

## 安全与错误处理

- 保存前校验必填字段和格式；更新凭据采用整组替换，断开时删除安全存储中的 provider 凭据。
- 固定 provider endpoint，不接受用户自定义 URL，避免将密钥发送到任意主机。
- 所有请求设置连接与读取超时、响应体上限和 HTTPS 约束。外部错误只转换为有限的安全错误类别，异常正文及 URL 查询参数不写日志。
- 将认证失败、权限不足、无可下载账单、平台限流、网络故障、响应格式错误和摘要不匹配分别映射到可重试或需修改配置的提示。失败测试不清除既有凭据，也不产生账本写入。
- Binance 与 OKX 的连接向导明确要求禁用 Trade/Withdraw 权限；若连接权限超出只读范围，应用不因此调用任何写端点。

## 扩展边界

通用连接模型区分支付账单 provider 和市场/账户 provider。provider 能力以具体接口显式声明；「可连接」不代表具备交易能力。新增交易所需要新增 provider adapter、凭据定义、只读调用、响应校验和测试，然后在连接卡片目录启用该 provider。

## 验收标准

1. 导航同时保留「法币汇率」并新增「交易所」；三家市场 provider 显示真实配置/连接状态，后续交易所只显示占位。
2. 微信支付与支付宝能通过商户凭据对用户选择日期执行真实只读账单请求；微信下载文件摘要不匹配时失败且不展示为成功。
3. 币安和欧易通过只读权限返回账户摘要；iFinD 能刷新 access token 并返回测试标的行情。
4. Rust 测试覆盖各签名/认证构造、凭据校验、错误映射、无账单、限流、超时、坏响应、摘要不匹配和无密钥泄露的 DTO；前端测试覆盖配置、掩码、测试状态和占位状态。
5. `cargo test --workspace`、UI 测试、UI 构建与格式检查通过；Android arm64 构建通过。Android 真机检查凭据可保存、重启可读取、断开可清除。
6. 在用户未提供正式 API 账号前，自动化协议和模拟响应测试不表述为真实平台联调成功。真实账号请求只在用户本机配置凭据后验证，不要求用户通过聊天发送密钥。

## 实施前限制

真实账单、账户余额和 iFinD 行情访问取决于账号主体、产品权限、平台地区和用户配置的凭据。API 官方文档规定了签名与权限要求，但当前工作区没有这些凭据；因此自动化验证可以证明签名、解析和错误边界，不能替代真实商户/交易所账号联调。
