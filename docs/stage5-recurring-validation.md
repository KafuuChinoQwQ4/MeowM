# 第五阶段：周期账单与到期提醒验收

验收日期：2026-10-16。范围对应九功能计划 Task 5，未开始 Task 6。

## 实现范围

- React 周期账单页支持创建、编辑未来实例、暂停、恢复、跳过下次和查看最近 200 个实例。字段包括人民币平台、收支、金额、分类、商户、说明、周/月/年周期、间隔、首次到期日和可选结束日期。
- 月末保留原始锚点，例如 1 月 31 日 → 2 月 28 日 → 3 月 31 日；闰日按目标年份夹到月末，后续闰年恢复 2 月 29 日。结束日期包含当天。
- 到期生成 Pending，不计入正式收支、余额或预算；用户经现有收件箱确认后入账。来源标记为 recurring，可筛选，附有模板和计划日期证据。
- SQLite 迁移 7 保留旧模板、交易和来源 ID，补齐旧模板日历锚点。候选、来源证据、唯一实例收据和模板游标在同一事务提交，两个连接同时生成、进程重启或重复刷新均不重复记账。
- 编辑使用版本检查；金额及平台修改只影响未来候选。已生成实例保留原金额，确认、忽略、恢复状态由关联交易派生。跳过保存独立收据，不创建虚假交易；暂停保留历史，恢复后补生成到期项。
- 首页展示未来 7 天、到期与逾期待确认项目；待确认提醒使用候选快照，确认或忽略后移除。点击已有候选的提醒进入周期来源的待确认收件箱。
- 日历、应用服务、存储映射/生成/写入、IPC 输入/返回/命令、React 表单/列表/历史/提醒及样式分别拆分。

## Android 实际链路

使用 JDK 17、NDK 26.1.10909125、API 35 x86_64 模拟器。安装保留数据，测试前备份账本，测试后恢复原文件并核对摘要。

1. 安装 x86_64 调试 APK，实际 WebView 经 Tauri IPC 打开旧版账本，`schema_version` 从 3 自动升级到 7，完整性检查为 ok，外键检查无错误。
2. 创建昨天到期的 12.34 月度支出，真实 SQLite 生成一条 recurring 来源 Pending。生成前后当日支出、余额不变。将模板未来金额编辑为 20.00，已有候选和首页逾期提醒仍为 12.34。
3. 跳过下一次到期、暂停模板，再创建明天到期的每周订阅。首页同时显示逾期待确认和即将到期；未来订阅尚无候选。点击“查看待确认”后，实际页面选择 recurring 来源并显示对应候选。
4. 强停并重启应用，模板金额、暂停状态、跳过收据均保留，生成数量为 0、候选只有原来一条。恢复模板后仍不重复生成。
5. 从实际 IPC 确认原候选，当日支出从 0.00 变为 12.34；实例状态为已确认，原逾期提醒消失。周期管理页显示未来金额 20.00、启用状态和跳过后的下一日期；实例弹窗显示 12.34 已确认和下期已跳过。320 CSS 像素宽度无水平溢出。
6. 恢复验收前原账本，测试模板、交易和候选不留在原账本中。

共享 Cargo 缓存首次跨 worktree 构建时缺少 Tauri 自动生成的 Kotlin 文件；按已安装依赖模板重新生成忽略的构建文件后，两种架构打包通过。未修改第三方依赖或提交生成的框架代码。原有 Android SDK 兼容性和弃用提示仍存在。

## 提醒边界

当前为应用内提醒：打开应用、回到前台、手动刷新及可见页面每分钟检查。应用关闭时不运行后台调度，也不发送 Android 系统通知或闹钟。每次检查最多生成 200 个到期实例，历史积压可继续生成；首页提醒最多 200 项，每个模板展示一个尚未生成的下一期，实例历史展示最近 200 个。

支持每周、每月、每年与 1～120 个单位的间隔；首次计划年份为 1900～9998。生成按设备当前本地时区的计划日午夜定位；不存在的本地日期返回错误并回滚整次生成。跨时区策略已做固定时区与夏令时测试，未做真机手动切换时区的长期运行验收。ARM64 APK 已构建，未安装到 ARM64 真机。未重复执行第四阶段未改动的通知 instrumentation。
