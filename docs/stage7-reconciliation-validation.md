# 第七阶段：账户对账验收

验收日期：2026-10-16。对应九功能计划 Task 7，未进入加密备份和恢复阶段。

## 实现范围

- 按平台、本地截止日末和实际余额生成快照，保留当时参考金额/时刻、账本金额、实际金额、差额及期间流水的金额、状态、商户、备注。计算只纳入 Confirmed；Pending/已忽略流水仍可逐项核对，但不会自动确认。金额由 Rust 整数分计算，IPC 用字符串。
- 首次快照覆盖截止前所有关联该平台的流水，后续从最近一个更早截止的已关闭会话之后开始；截止时刻包含精确微秒边界。所有历史金额和流水字段不可原地修改，核对状态和会话版本独立更新。
- 核对全部流水后，填写原因并明确确认，才生成一笔 `BalanceAdjustment`。交易、会话关联、余额验证和两类审计在同一立即事务提交；失败全部回滚。该调整不计收入、支出或预算，普通交易编辑和撤销不能改写它。同会话同原因的重试返回原调整 ID；不同原因不能重复调整。
- 关闭要求逐项核对和差额已解决，重复关闭幂等；重新打开保留原始快照、调整和审计。调整或关闭前校验最新参考点及截止余额，发生变化时要求新建快照。版本冲突要求刷新。截止日末不晚于参考时刻时不允许生成调整。
- React 按页面、创建表单、会话操作和流水列表拆分；独立 API、样式及 Rust 命令/返回类型模块。支持缺少参考余额时跳转设置、Pending 收件箱和当前交易详情。失败保留输入，移动端金额和按钮可换行。
- 数据库迁移 9 保留版本 8 及更早数据；旧占位对账会话只读，不能伪造其缺失的历史快照。新字段、快照和调整关联由数据库约束/触发器保护。

## Android 实际链路

使用 API 35 x86_64 模拟器、JDK 17、NDK 26.1.10909125。覆盖安装后通过实际 WebView 调用 Rust，未注入模拟 IPC：

1. 新建临时平台，缺少参考余额时开始对账返回明确提示；设置 -100 元参考余额，录入 1 元已确认支出和 2 元到期 Pending。
2. 使用实际 React 页面选择平台、截止日和 -102 元实际余额。快照返回账本余额 -101 元、差额 -1 元，包含两条期间流水，其中 Pending 为 1；Pending 没有影响余额。
3. 页面逐项核对、输入原因、接受确认弹窗后生成调整，再关闭、重新打开并再次关闭。实际日汇总余额为 -102 元，支出仍为 1 元、收入为 0；仅有一个 adjusted 事件。页面在模拟器视口没有横向溢出。
4. 新建下一日快照后补录 0.50 元支出，再请求调整被拒绝。旧快照仍保留原账本金额 -102 元，未生成调整。
5. 强制停止并重新启动应用，逐字段比较快照、closed 状态、调整 ID 及全部 7 条审计事件，结果一致。实际活动库版本为 9，`integrity_check` 为 ok，`foreign_key_check` 为空。

## 边界

对账是用户输入的本地核对记录，不连接支付平台或银行。没有关联平台分录的 Pending 不在快照内，须先在待确认流程补全。审核 Pending 只表示看过快照，不替代确认入账；以后确认导致截止余额变化时须新建对账。

单次读取完整期间流水，适合个人账本规模；未增加后台批处理或分页快照。会话列表以创建时间排序，历史截止日期可重复创建，旧会话不会被覆盖。已创建调整不能通过普通编辑/撤销回改，后续修正需新建对账并留下新的原因审计。当前只在 x86_64 模拟器验收，未执行 ARM64 真机测试。
