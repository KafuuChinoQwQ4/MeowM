# 第九阶段：隐私控制和数据生命周期验证

## 实现范围

应用启动先查询 Rust 中的锁状态；启用应用锁后，重启默认锁定，账本 IPC 在解锁前拒绝读取。密码只在本机以带随机盐的 Argon2id 验证值保存；连续错误尝试有限速。前台活动重置 1 至 120 分钟的自动锁定计时，隐藏金额只遮盖界面。Android Activity 使用 `FLAG_SECURE` 防止系统截图和最近任务缩略图显示应用内容。

通知来源开关沿用原有授权页面。删除通知数据前展示候选、已确认交易、收据和被引用候选数量；删除命令要求十分钟内的预览 ID 和准确确认短语，并在 SQLite 立即事务内核对账本指纹。清理会关闭通知来源、删除来源证据和未确认候选，保留已确认交易与分录，并写入来源清理审计。历史对账、退款及其他来源引用阻止单独删除。全部数据清理采用相同预览机制，清除本机锁设置，重建三个默认空平台并写入删除审计。

## 验证

- `cargo test --workspace --quiet`：真实 SQLite 用例通过，覆盖锁定重启、错误密码和限速、自动锁定、事务失败回滚、预览失效、历史引用阻断、已确认交易保留和全量清理。
- `cd apps/tauri-ui && npm run test:ui`：23 个浏览器流程通过，包括锁屏阻止账本加载、解锁、金额遮盖和删除短语确认；浏览器 IPC 为模拟层。
- `cd apps/tauri-ui && npm run build`、Prettier 检查、Rust fmt、Clippy、目录索引检查和 Android x86_64 debug APK 构建均在本阶段完成。
- Android API 35 x86_64 模拟器安装阶段构建的 APK，在真实 WebView 和 Rust IPC 中验证隐私页面、错误密码拒绝、锁定后账本命令拒绝、解锁、金额遮盖切换、来源和全量删除预览。错误确认短语被拒绝；全量删除后剩下三个空平台及一条删除审计。验证前的活动数据库已按原 SHA-256、所有者及权限恢复。
- 源代码检查关注通知正文、key、密码、Token、金额及日志路径；待上传文件、暂存区、Git 历史和 APK 再做静态扫描后发布。

## 边界

模拟器流程没有覆盖真实微信或支付宝通知、Android 不同厂商的后台行为，也未验证实际闪存擦除。来源关闭会停止新采集，已有数据保留到用户明确选择删除；已确认交易不随通知来源清理而删除。应用内删除不会删除用户已经保存到外部的备份、导出或系统级副本。SQLite `secure_delete` 尽量清理数据库空闲页，不能保证闪存或系统备份的物理擦除。第十阶段仍需完整端到端发布验收。
