# 第六阶段：搜索、商户归一化与分类规则验收

验收日期：2026-10-16。范围对应九功能计划 Task 6，未开始账户对账。

## 实现

- 跨日期流水搜索组合状态、来源、平台、分类、起止日期、商户、关键词和人民币金额范围。关键词匹配规范化商户、原商户、备注及来源外部交易号；SQL 元字符按普通文本处理。分页按时间倒序及交易 ID 打破同时间并列，数量和结果在同一读取事务中获取。筛选参数、页长与偏移量均绑定，不拼接用户输入。
- 原始商户字符串保留显示，`merchant_normalized` 另存去首尾空白、折叠中间空白、小写后的值；本地别名表将规范化别名映射到规范商户。迁移 8 为旧行回填并保留所有旧交易、分类、规则、来源 ID。
- 分类和规则管理页可新增或停用分类、维护别名、创建或编辑规则。规则按优先级与 ID 稳定选择，停用分类不产生新建议。预览同时展示匹配总数和保存后建议会变化的未手工分类 Pending 数量及最多 20 个样例；点击确认后保存规则。
- 建议在待确认收件箱和编辑器展示，用户点击“采用建议”才写入候选分类。已手工分类的 Pending 和已确认交易不会被规则修改。别名变更通过动态建议与搜索立即生效，不批量改写原流水。
- 搜索页可清除筛选、分页、打开交易详情，以及将当前已提交筛选的所有结果导出为 UTF-8 CSV；CSV 对公式开头的单元格加文本前缀。

## Android 实际链路

使用 API 35 x86_64 模拟器、JDK 17 和 NDK 26.1.10909125。覆盖安装保留数据，测试前备份模拟器原账本；验收结束后恢复原文件，逐字节及 SHA-256 校验一致。临时导出的 CSV 已删除。

1. 旧账本由版本 3 自动升级到 8，SQLite 完整性检查为 ok。实际 WebView 可进入“搜索与分类”。
2. 经真实 Tauri IPC 创建临时分类、中文商户别名及到期 Pending。按规范商户大写关键词及 10～20 元范围能检出原文商户、金额 12.34 的候选；生成前不自动确认或写入分类。
3. 真实规则预览返回总命中 1、影响 Pending 1；保存后候选返回规则 ID、分类 ID 和原因，但交易 `category_id` 仍为空。实际 React 待确认编辑器显示建议；分开点击“采用建议”“保存并确认”后，交易分类写入预期 ID。
4. 点击搜索页“导出当前结果”，Android 打开系统 Downloads 的“另存为”选择器。选择保存后读回 CSV，包含表头和临时商户，共 4 条数据行；测试文件随后删除。

第一次自动脚本连续触发“采用建议”和“保存并确认”，同一浏览器任务里 React 尚未提交状态，因而没有采用分类。按实际两次点击时序复测成功，证明 UI 状态更新与持久化链路正常。

## 边界

搜索按当前 SQLite 快照分页；在不同页请求之间新增或编辑交易会改变总数及页位置，界面可重新搜索。关键词包含匹配在大量记录上可能逐行扫描，已有时间、金额和商户规范化索引不等于全文索引。分类规则预览遍历本地交易以准确计算变化数量，适合个人账本规模；未实现后台批处理或全文引擎。来源原文隐私摘要不可逆，搜索仅匹配允许持久化的外部交易号。CSV 在桌面由 Playwright 验证文件内容；Android 使用系统“另存为”，单次上限 16 MB。当前只在 x86_64 模拟器实测，未在 ARM64 真机执行。
