# 多币种账户与外币记账设计

## 目标

在现有 CNY 账本中支持 USD、EUR、JPY、HKD、GBP、KRW、AUD、CAD、SGD、CHF 账户的手工收入、支出、退款和同币种转账。账户余额以账户原币记账；跨币种收支按交易日期的参考汇率折算为 CNY 纳入现有收支统计，并在确认时固定折算结果和汇率证据。

## 范围

### 本期包含

- 新建平台时选择 CNY 或汇率历史页面已支持的十种外币。现有账户与历史交易不迁移金额，既有账户默认继续为 CNY。平台列表、账本和流水详情显示币种。
- 账户原币金额继续以整数最小单位保存。币种小数位采用稳定的应用规则：JPY、KRW 为 0 位；CNY、USD、EUR、HKD、GBP、AUD、CAD、SGD、CHF 为 2 位。未知币种不可创建。
- 手工记账支持外币收入、支出、退款和同币种转账。输入金额解释为所选账户的原币金额。退款必须与原消费使用相同币种；转账双方币种必须完全相同。跨币种转账不在本期提供。
- 收入、支出和退款进入 CNY 报表。CNY 账户直接使用原金额；外币流水使用交易日期不晚于该日的最近一条已缓存参考汇率。参考汇率约定为 `1 CNY = rate 外币`，CNY 金额按 `外币金额 / rate` 计算到 CNY 分，并用十进制整数运算四舍五入到分。
- 本地没有可用参考汇率时，手工录入允许填写折算率，明确以 `1 CNY = rate 外币` 表示。录入参考汇率或手工汇率均记录汇率文本、有效日期、汇率类型和来源键；手工汇率使用交易日期及 `manual` 来源。自动汇率缺失时不猜测、不使用交易日之后的数据，也不阻止原币交易保存。
- 每条外币收入、支出和退款保存确认时的 CNY 折算金额及不可变汇率快照。后续日常同步或供应商修订历史观察不会回算、更改已确认交易及旧报表。
- CNY 报表的收入、支出、分类、商户和趋势继续使用保存的 CNY 分值。账户余额、期初余额和对账金额始终使用账户原币；报表余额逐账户显示原币及币种，不将异币余额求和或伪装成 CNY。
- 账单导入、通知与支付页采集、周期模板、预算及规则自动生成继续按 CNY 工作。外币账户不出现在这些 CNY 专用确认或生成流程的可选列表中；已有 CNY 数据和流程保持原行为。

### 本期不包含

- 跨币种转账、转账手续费或不同的转出与转入金额。
- 汇率历史自动改写历史分录、按当前汇率重估账户余额、投资估值或多币种净资产总额。
- 外币账单解析、通知识别、周期模板、预算以及外部交易的自动导入。
- 汇率供应商以外的在线兑换报价、用户账户同步或服务端存储。

## 方案选择

推荐沿用现有分录模型的原币金额，并继续把 `report_amount_cny` 作为 CNY 报表金额。增加与交易一一对应的可选 FX 快照，保存换算证据；交易写入、修改和状态变更继续经过现有应用服务与 SQLite 事务边界。现有账户和分录已有币种字段，因此不重写历史分录，也不把外币伪装成 CNY。

不采用“所有账户余额都先折 CNY”的方案：这会让账户余额不能与实际币种对账，也会让历史余额随汇率变化。不采用“各币种分开统计且不换算”的方案：这会割裂当前所有金额以 CNY 展示的总收支、分类和月度报表。

## 币种和账户行为

- 扩展账户创建命令接受规范化币种代码，省略币种时保持兼容并默认为 CNY。查询账户时返回 `currency_code` 和 `currency_exponent`。
- 币种选择列表只展示 CNY 加十种已支持汇率的币种，并显示中文名称、代码和小数位说明。
- 编辑已有账户时币种只读；币种创建后不可修改，避免历史分录的币种语义改变。账户名称和分类继续可编辑。
- 创建命令验证代码和预设小数位；客户端参数不能指定任意小数位。
- 流水录入、交易详情、当日流水金额和账户余额使用账户币种格式化。记录同时展示折算 CNY 值；转账显示两端相同的原币金额且不生成收入/支出或 CNY 折算额。

## 汇率选择和精确折算

1. 取交易本地日期 `D` 与账户币种 `Q`，查询本地历史中 `quote_currency=Q` 且 `effective_date <= D` 的最新观察。
2. 若找到观察，按原精确十进制 rate 计算并保存 CNY 分；快照保存 CNY 基准、Q、原 rate 字符串、观察有效日期、`frankfurter` 来源名及供应商来源键。
3. 若找不到观察，界面展开必填的手工汇率输入。有效范围和格式校验与存储层十进制精度约束一致；快照保存手工 rate、D、`manual` 类型，不伪称为 Frankfurter 数据。
4. 对原币正金额按 `round(amount_minor × 100 × 10^rate_scale / (10^currency_exponent × rate_coefficient))` 计算 CNY 分，使用有界整数或任意精度十进制/整数算术；中间溢出返回本地化校验错误，不写交易。不得用二进制浮点数确定持久化 CNY 分。
5. 退款沿用退款交易日期对应的参考或手工汇率；原消费只约束币种和原消费关联，不重用旧消费汇率。
6. 汇率服务返回的周末/节假日日期是观察真实有效日，交易快照保存该日；手工汇率快照使用交易日期。来源键只允许安全的已验证字符串。

## 数据和交易不变量

- 新 schema 版本为 14。增加每交易至多一条 FX 快照表，外键级联删除；包含交易 ID、基准/目标币种、精确 rate 文本、有效日期、类型（`reference`/`manual`）、来源和安全来源键。
- 现有 `transactions.report_amount_minor`、`report_currency_code`、`report_currency_exponent` 列继续保存 CNY 收支金额（币种代码 `CNY`、小数位 2）；所有非转账外币收支/退款写入正数 CNY `report_amount_cny` 和有效 FX 快照。CNY 交易、转账、无报表折算的记录没有 FX 快照。历史记录升级后不创建虚假快照。
- 外币交易 posting 的 `currency_code` 和 `currency_exponent` 必须与账户一致。转账两端的币种代码和小数位必须一致，且原有借贷方向、等额、非零检查仍生效。
- 外币 FX 快照的目标币种必须等于交易 posting 币种、基准必须为 CNY、rate 必须为正的规范十进制。参考快照必须带 Frankfurter 来源与有效观察日期；手工快照必须使用 `manual` 类型、空供应商来源列表和交易日期。
- 交易插入、编辑、删除/撤销、加密备份、快照导出/导入及 schema 13 恢复升级共同处理 FX 快照，避免出现折算金额缺快照、孤立快照或部分保存。
- 每当外币流水金额或日期改变，必须重新选择或录入汇率并在用户预览前返回新的 CNY 金额与快照；汇率仅变化而金额与日期未变时，编辑不静默重估已存流水。

## 组件和接口影响

- `ledger-domain`：保留 posting 的原币 `Money` 与 CNY `report_amount_cny` 语义；新增可选 FX 快照类型并扩展交易结构验证。验证收入、支出、退款的 CNY 报表币种和快照一致性，以及同币种转账。
- `ledger-storage`：迁移 14、FX 快照持久化/映射/验证和可信快照表清单；测试历史升级、往返、外键和备份恢复。
- Tauri ledger commands：账户 DTO 返回币种；创建账户可选币种；手工交易保存请求可选手工汇率；保存响应或详情返回本币金额、CNY 金额和快照证据。获取汇率取本地 SQLite，不让 WebView 直接调用网络。
- React：账户表单增加只在创建时启用的币种选择；手工流水根据账户币种显示正确金额标签和精度；无可用观察时要求输入手工汇率；确认预览展示原币金额、汇率来源/有效日及 CNY 分值；列表和详情同时显示原币与 CNY 金额。
- 兼容性：所有已有 IPC 请求缺省币种为 CNY，所有老记录没有 FX 元数据时仍按原行为读取；不重命名破坏旧调用方的命令或字段。

## 错误与隐私

- 不支持的币种代码、超出预设小数位的金额、非正/畸形汇率、超范围汇率、中间计算溢出、转账币种不匹配或外币退款币种不匹配均在持久化之前拒绝。
- 本地查不到参考汇率时显示可执行的“填写手工折算率”状态；不可用网络、缓存未命中或 provider 故障不丢弃用户已输入的原币金额。
- FX 快照只存币种、汇率、日期和安全来源标识；不新增账本金额到汇率请求。现有网络请求仍仅包含固定币种和日期范围。
- 加密备份与恢复保护账户币种、原币分录、CNY 折算额和 FX 快照为同一账本状态。

## 验收标准

1. 新建账户可以选 CNY 或十种支持外币；旧 IPC 不传币种时仍创建 CNY；账户列表显示币种，编辑不能改变币种。
2. USD 账户可记 USD 账户最小单位的收入/支出，posting 和余额保留 USD；具有交易日或此前汇率时，CNY 报表金额精确折算并四舍五入到分。
3. JPY/KRW 输入整数，不接受小数；2 位币种接受最多两位小数，录入与显示均不出现浮点持久化误差。
4. 存在多条历史观察时选择最新的不晚于交易日期一条；晚于交易日期的汇率不得用于交易。周末交易可采用之前最近的实际观察日期。
5. 无历史汇率时要求用户提供手工汇率；保存的交易详情可见手工类型、交易日期和原 rate；缺失输入、零、负值、格式错误和溢出均不会写交易。
6. 账户原币流水余额正确；仅同币种转账可保存；跨币种转账被前端及领域验证拒绝且不产生部分分录。
7. 外币退款只能关联同币种原消费；折算采用退款日期的汇率，净 CNY 报表与退款方向正确。
8. CNY 报表继续汇总 CNY 与外币收支的已保存折算金额；转账不计收入/支出；账户余额逐币种展示，不把不同币种相加。
9. 历史 CNY 交易、导入、通知、预算、周期模板和旧快照升级行为保持不变；schema 14 加密备份往返保留每个快照字段。
10. Android 真机验证可以创建外币账户、保存一笔外币手工交易、重开查看原币和 CNY 金额，并确认已注册的每日汇率任务仍在应用 Activity 关闭后保留。

## 验证范围

- Rust 单元和集成测试覆盖固定汇率与手工汇率的整数折算、边界舍入、货币小数位、观察日期选择、溢出、领域约束、迁移和加密备份。
- Tauri 测试覆盖账户兼容默认值、创建外币账户、手工交易、汇率缺失/错误和 CNY 报表金额。
- React 工作流测试覆盖币种创建、录入标签/精度、手工汇率预览、跨币种转账拒绝，以及详情中双金额和快照来源。
- 运行 Rust 工作区、前端 UI/格式/构建检查和 Android universal debug 构建；在当前 USB Android 设备执行针对性 instrumentation 与实际录入/重开验证。
