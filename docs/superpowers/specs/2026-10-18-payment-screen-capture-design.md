# 支付成功页面识别设计

## 目标和边界

在 Android 用户授权期间，用本地 OCR 识别微信、支付宝支付成功页面，自动保存到现有待确认收件箱；确认前不改变余额。通知来源与屏幕来源独立开关和配置默认人民币平台。未配置平台仍可产生待补全候选。

用户主动启动系统 MediaProjection 授权；前台服务显示通知并提供停止动作。使用情况访问权限用于获取系统前台包名，只处理 `com.tencent.mm` 和 `com.eg.android.AlipayGphone`。Android 13 以上先请求通知权限，关闭应用或捕获通知频道时不能启动。每次重新启动都重新授权，进程死亡后不自动恢复。

## 数据流

1. `ScreenCaptureCard` 保存独立来源设置，调用 Rust `start_screen_capture` 创建临时会话；Kotlin 插件请求通知和屏幕授权。取消或启动失败撤销该会话。
2. `PaymentCaptureService` 只创建一次 VirtualDisplay，旋转使用 resize 和换 surface；最新 Image 替换旧帧，定时器约每秒消费一帧，最长边限制 1280 像素。静止屏幕完成两次 OCR 后最多缓存三秒；为冷启动识别保留第二次采样机会，硬上限三十秒，以免静态页面不再产生新帧而漏采。
3. bundled ML Kit 中文识别在本机处理。前后均核对当前包名、来源开关、会话及应用锁；两次相同 OCR 结果生成当前连续成功页面的事件 ID。离开成功页两次或切换应用后开始新页面，重试沿用同一 ID。
4. JNI 使用现有 `LedgerState` 互斥锁与真实隐私状态，不新建绕过应用锁的账本上下文。原文只作为短时解析参数；持久化标准化金额、商户、捕获时间、方向、来源摘要及结果码。
5. SQLite migration 10 增加屏幕设置、状态、收据和匹配元数据，原子写入 Pending、证据与收据。快照、恢复和隐私清理包含全部新增表。

## 识别与重复处理

支持成功关键词和保守的人民币金额、商户字段解析。缺失字段要求补全；退款必须关联原消费，转账必须补全两平台。记录时间使用识别时刻，未从页面解析实际交易时间或订单号。

同一屏幕事件 ID 自动去重；通知保留原有 identity/digest 去重。屏幕与通知在同应用、同方向、同平台、同商户、同金额且相隔十秒内有唯一匹配时，只在新候选备注中提示疑似重复并引用已有记录。金额与时间不足以证明同一笔支付，不能自动合并，以免漏记不同的同额支付。用户在收件箱确认或忽略。重新打开旧支付页面、重启服务可能再次产生候选。

## 隐私和资源

原始截图、OCR 全文不写文件、不上传、不写业务日志；只在受限的帧缓存与 OCR 调用内存中存在，处理完成回收，离开支持应用清理缓存。常驻通知关闭、使用情况权限撤销、投影结束、锁屏、应用锁定或停止操作会使会话失效并释放资源。异步 OCR 在返回时重新验证，不允许晚到结果在停止后写入。后台轮询不延长应用锁的活动时间。

隐私页“删除通知数据”同时预览并清理屏幕来源候选和收据，保留已确认分录；恢复备份与删除数据前使捕获会话失效。备份保留来源设置，不包含系统授权或活跃会话。

## 验证范围

Rust 覆盖解析、持久去重、两种来源到达顺序、独立同额支付、恢复、应用锁和停止后拒绝写入。Kotlin 单元测试覆盖页面去重及失败重试 ID。浏览器测试使用模拟 IPC，覆盖设置草稿、用途同意、权限状态、取消与启动停止。Android 编译验证原生 API 和 JNI 集成；真实支付格式、禁止录屏页面、长期功耗与厂商后台限制仍需实机验收，不能据此承诺捕获每笔支付。
