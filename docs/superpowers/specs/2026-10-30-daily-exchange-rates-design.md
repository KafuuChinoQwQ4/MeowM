# 每日汇率更新与趋势图设计

## 目标

在 MeowM 中增加可离线查看的每日汇率历史和曲线图。Android 在应用界面关闭后继续尝试更新；桌面版在应用运行时检查更新。该汇率服务作为后续多币种账务的基础，但本规格只实现汇率数据、同步和展示，不改变账户或交易的币种语义。

## 范围

### 本期包含

- 以人民币（CNY）为基准，保存 USD、EUR、JPY、HKD、GBP、KRW、AUD、CAD、SGD、CHF 的每日参考汇率。
- 使用 Frankfurter v2 公共接口的默认混合数据。请求最新数据、日期范围和来源信息；不发送账本、账户或交易数据，不需要用户 API 密钥。
- 在本机 SQLite 保存汇率观察值、来源和同步状态；更新幂等，断网、超时或数据无效不覆盖已有记录。
- Android 使用 WorkManager 的唯一周期任务，要求有网络时运行并启用失败退避；任务启动后通过现有 Rust JNI 桥接入口调用 Rust 汇率服务，复用同一 SQLite 迁移、校验和写入代码。
- 每次 Android 前台启动时安排/确保周期任务，并请求一次即刻同步。手动刷新也调用相同的 Rust 服务。
- 桌面版在启动及汇率页手动刷新时更新；桌面应用进程退出后不安装系统级计划任务。
- 在「财务管理」中增加「汇率趋势」入口。用户选择目标币种和 30、90 或 365 个自然日范围，查看 1 CNY 对应外币数量的 SVG 折线图、最新观察日期、最近同步状态和来源说明。
- 允许离线查看已保存数据。周末及来源未发布数据的节假日不插入伪造观察值；图表按实际观察日期连接。
- 把汇率数据纳入 schema 迁移、快照校验、加密备份和恢复。

### 后续多币种账务项目

下一项相连工作将使用这里的历史汇率，扩展多币种账户、交易、退款、跨币种转账及人民币报表折算。当前项目不更改账户币种选择、交易分录、预算、账单导入或支付采集的既有行为。

## 方案选择

采用本机汇率服务和 Android WorkManager，并让 UI、前台刷新和后台任务共享 Rust 实现。UI 直接请求第三方服务并自行缓存会绕开 Rust/SQLite 的数据校验和备份边界，也无法可靠提供应用关闭后的更新。自建服务或常驻后台进程会增加托管成本、用户数据暴露面和电池消耗，而汇率只需低频拉取。

Frankfurter v2 支持按基准货币、目标货币及日期范围查询每日和历史数据；其文档允许客户端缓存观察值。应用使用聚合参考数据，不把它描述为实时交易报价。日期始终使用服务返回的有效日期，而不是本地请求日期；周末或假日沿用最近一次已发布观察值时，界面显示该实际日期。

## 架构和数据流

1. Android 原生入口以唯一名称注册 24 小时周期 WorkManager 任务，网络连接是执行约束，并配置指数退避。Worker 可在 Tauri Activity/WebView 未运行时工作；它只调用 `RustBridge` 的受限 JNI 方法，不处理汇率逻辑或直接写 SQL。
2. Rust 汇率模块构建固定币种和日期范围请求，设置连接/读取超时，限制响应体大小，检查 HTTP 状态、JSON 结构、日期、币种集合以及正有限十进制汇率。只有完整验证后的批次才以 SQLite 事务写入。
3. 新安装首次同步获取最近 365 个自然日；之后从本机最新有效日期补齐到服务最新日期。相同日期、基准和目标币种采用唯一键去重。服务端没有新交易日时，保留原历史并将同步标记为无新数据。
4. 同步状态只保存安全的状态码、尝试/成功时间和错误类别；不保存原始响应正文、个人账务内容或可能带查询参数的 URL。已验证汇率观察值是可移植数据并随加密备份恢复。
5. Android 冷启动触发一次尽快同步，以免等待下一次周期窗口；桌面启动同样检查并补齐。汇率页提供显式重试。每个入口调用同一同步应用服务。
6. React 查询本地历史，按有效日期排序并绘制 SVG。没有数据时显示空状态；本地有旧数据而刷新失败时继续展示旧曲线，同时标出最后有效日期和重试入口。

## 数据契约

每条汇率观察值包括：

- 服务有效日期（ISO `YYYY-MM-DD`）。
- 基准币种 `CNY` 和目标币种代码。
- 精确十进制汇率文本；不得经由二进制浮点数舍入后持久化。
- 数据聚合来源标识和可选贡献来源清单。
- 获取时间 UTC 微秒。

主键为 `(effective_date, base_currency, quote_currency)`。初始支持币种及其最小货币单位指数为 CNY 2、USD 2、EUR 2、JPY 0、HKD 2、GBP 2、KRW 0、AUD 2、CAD 2、SGD 2、CHF 2。后续加入币种必须同时验证来源覆盖和最小单位元数据。

同步状态独立保存最近尝试时间、最近成功时间、状态（成功、有无新数据、网络错误、超时、来源错误或校验失败）及非敏感错误类别。同步失败不得删除汇率历史。

## 界面行为

- 「财务管理」目录新增「汇率趋势」，描述中说明显示每日参考汇率。
- 页面默认选择 USD 和最近 90 日；币种和范围通过可访问的选择控件更改。
- 图表为响应式 SVG，纵轴显示每 1 CNY 可兑换的目标币种数量，横轴按服务有效日期取样；支持触屏/鼠标查看单点日期和精确汇率。
- 清晰标示数据源和“参考汇率，非实时交易报价”。周末空档不显示为零、不伪造当天汇率。
- 显示最后有效汇率日期、最近同步时间和状态；用户可手动刷新。刷新失败保留输入和已有曲线，显示本地化重试信息。

## 失败处理、隐私与兼容性

- 网络不可用、HTTP 错误、响应超限、JSON/日期/币种无效或汇率非正数时，拒绝整批写入并保留本地历史。
- Worker 对可恢复错误返回重试，使用 WorkManager 退避；周期任务执行时刻受 Android 网络和省电策略影响，不承诺在某个精确时刻完成。设备强制停止应用或厂商后台限制可能延迟任务；应用再次启动时补齐。
- 前后台并发同步依赖唯一计划任务、SQLite busy timeout 和幂等主键，不会产生重复观察值。
- 数据请求只包含 CNY、固定目标币种和日期范围；不发送任何账本数据，也不在日志中输出完整 URL、响应正文或网络异常正文。
- 数据库升级保持原有账户及交易值，增加新的汇率表。可信迁移、快照重建与验证必须包含新表；旧版备份仍可恢复，恢复后继续升级到当前 schema。
- 该服务只在数据同步时需要网络；查询历史和绘图完全本地运行。

## 验收标准

1. 最新和历史 API 响应经过校验后写入 SQLite；重复响应幂等，服务端无新观察值不会制造新日期。
2. 超时、无网络、错误状态码、超大响应、缺失币种、无效日期、非正汇率均不修改已有数据，并给出可重试状态。
3. 首次 365 日回填和较短缺失日期补齐返回服务实际有效日期，周末/假日没有伪造记录。
4. Android 周期任务在首次应用启动后只注册一份，能经由 Rust 桥接更新真实数据库，并配置联网约束与退避；桌面退出后无计划任务的边界在设置/说明中清楚。
5. 汇率页按所选币种和范围显示本地数据，能用单点查看有效日期和汇率；空数据和同步失败状态可访问且能重试。
6. 新增历史在加密备份恢复后保持相同，旧版本快照仍可升级；畸形历史不能绕过服务校验进入正式库。
7. 现有 CNY 账务、图表、账单导入、隐私锁和备份工作流保持原行为。

## 验证边界

自动化验证覆盖 Rust API 解析/校验/存储、迁移与快照往返、图表范围和空/错误状态、Android Worker 注册及 JNI 调用边界。除非在真实 Android 设备上验证 WorkManager 生命周期和厂商后台策略，不宣称已证明所有设备都会按时运行。公共服务可用性和汇率覆盖可能变化；UI 显示服务返回日期并允许重试。
